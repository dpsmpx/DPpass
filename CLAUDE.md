# CLAUDE.md — как работать в репозитории DPpass

Правила для всех, кто меняет код и документы DPpass, — людей и
ИИ-ассистентов. Короткая версия: **сначала решения и архитектура,
потом код; каждое изменение проходит hostcheck; ничего чужого и ничего
молча.**

## Что это

DPpass — клиент прокси/VPN для Android с собственной моделью
конфигурации, маршрутизации и подписок, рассчитанный на сети с
ограничениями (`docs/research/RUSSIA_NETWORK_RESTRICTIONS.md`). Ядро —
модули на чистом Kotlin/JVM; Android-приложение — оболочка над ним
(D-02). Ядро прокси — Xray в процессе приложения через свою обёртку Go
с JNI (D-24, D-25); фиктивное ядро осталось только вторым бэкендом в
тестах. Сервис туннеля подключает ядро; на устройстве подключение
ещё проверяется — этап 2 (`docs/direction/ROADMAP/README.md`).

С 16 октября 2026 DPpass — подсистема DPmetaApp, каталог `dppass/`
(D-52, `DPmetaApp:D-30`): репозиторий DPpass заморожен, работа идёт только
здесь. Все пути ниже — от `dppass/`, команды — из этого каталога. Правила
DPmetaApp (`DPmetaApp:CLAUDE.md`) действуют для всего репозитория, этот
файл — для подсистемы. APK DPpass пока отдельный, с прежней личностью
пакета; ядро — своё (D-52).

## Перед изменением

1. Найти решение, которое изменение затрагивает (`DECISIONS.md`), и
   раздел `ARCHITECTURE.md` про нужный модуль. Изменение, которое
   противоречит решению, начинается с нового решения, а не с кода.
2. Посмотреть `TODO.md`: возможно, задача уже описана или с ней связан
   известный долг.
3. Работа «заодно», не относящаяся к задаче, — строка в `TODO.md`, а не
   правка.

## Проверка

Проверки идут через DP Verify (D-50): копия — `tools/dpv/`, профиль —
`tools/dpverify.toml`; `run.sh` — обёртка с прежними ключами.

```sh
tools/hostcheck/run.sh --quick    # dpv run static — быстрые проверки без Gradle, перед коммитом
tools/dpv/dpv run affected        # после задачи: что выбрано и почему — tools/dpv/dpv plan affected
tools/hostcheck/run.sh            # dpv run full — всё, что есть на этой машине; пропуски — громко
tools/hostcheck/run.sh --full     # dpv run full --ci — перед слиянием: без Android SDK, NDK, Go — ошибка
tools/dpv/dpv report --md         # итог последнего прогона — в описание PR
```

Внутри DPmetaApp — те же ключи `tools/hostcheck/run.sh` из `dppass/`
(и `run.sh report` вместо `dpv report --md`): DP Verify идёт в
представлении поддерева, `--full` — только на закоммиченном `dppass/`
(D-52).

Подробно — `docs/PROCESS.md`, «Проверки»; что ловит проверка и как
чинить — `tools/dpv/dpv explain ID`. Изменение готово, когда проверки
зелёные; падающий тест не отключается и не ослабляется, а чинится или
становится решением; `tools/dpv/` руками не правится. **CI нет:** GitHub
Actions не используется и не запускается (D-23) — перед слиянием полный
прогон `--full` делается локально (`docs/PROCESS.md`, «Перед слиянием»).

## Правила кода

- **Ожидаемые отказы — `Outcome` с `Diagnostic`**, а не исключения;
  причина сохраняется цепочкой `causes` (D-22). Код `DiagCode` — публичный
  контракт: только добавлять.
- **Смысл не меняется молча** (D-05): то, что нельзя выразить, — ошибка
  с путём, а не «ближайшее похожее».
- **Секреты — `Secret`**, `reveal()` — только в разрешённых местах;
  журнал — только `Logger` (редактирование по умолчанию) (D-11).
- **Время — через `Clock`**, случайность — криптографическая или с явным
  зерном (D-21). Нет `Thread.sleep`, `GlobalScope`, `runBlocking` вне `cli/`.
- **Android — только в `app/`**; направления зависимостей модулей — по
  `docs/ARCHITECTURE.md`, §2.
- **Предупреждения компилятора и Lint — ошибки.** Не подавлять без
  причины в комментарии.
- Стиль — как в окружающем коде: KDoc объясняет «почему» и ссылается на
  решение; комментарии, документы и сообщения диагностики — по-русски,
  идентификаторы — по-английски.
- Новый баг — новый файл корпуса `tests/data/` (`docs/TESTING.md`).

## Оригинальность

- DPpass пишет **свой код**. Код, тексты, значки и данные других
  клиентов (Happ, v2rayNG, NekoBox, Hiddify, sing-box и др.) не
  копируются — даже если лицензия позволяет (D-20).
- «Так сделано у X» — не довод. Довод — свойство, нужное пользователю,
  или датированный факт из исследования. Сравнение с другими
  клиентами — только как факт (`docs/research/COMPETITOR_ARCHITECTURE.md`).
- Закрытые клиенты не декомпилируются, результаты чужой обратной
  разработки не используются (`docs/direction/RESEARCH_SCOPE.md`, §4).

## Происхождение

- Код неизвестного происхождения запрещён: «нашёл в интернете»,
  «сгенерировалось похожим на проект X» — не принимается
  (`docs/PROVENANCE.md`).
- Новая зависимость или версия — по чек-листу D-18 и только со
  строками в матрице лицензий и PROVENANCE (`provenance.deps` и
  `check_dependencies.py` проверяют).
- Двоичные файлы в репозитории — только записанные в PROVENANCE с SHA-256.

## Чего не делать

- Не публиковать релизную сборку до этапа 5 (подпись, R8, лицензии).
- Не добавлять телеметрию, аналитику, отчёты о падениях, идентификаторы
  устройства (D-12).
- Не принимать отключение проверки сертификата и не писать свои
  `TrustManager`/`HostnameVerifier` (`docs/SECURITY_MODEL.md`, T5).
- Не давать подписке менять поведение клиента без согласия
  пользователя (D-11).
- Не обещать «гарантированно работает», «незаметен», «обходит белые
  списки» — ни в коде, ни в документах, ни в интерфейсе (D-13).
- Не коммитить секреты, настоящие серверы и ключи — даже «тестовые»;
  в корпусе только синтетические данные (`security.secrets`,
  `data.synthetic`).
- Не поддерживать `happ://crypt*` и прочие ссылки, скрывающие
  конфигурацию от пользователя (`docs/research/HAPP_SOURCE_AUDIT.md`, §4).
- Не переименовывать и не удалять коды диагностики, не менять формат
  документа без новой версии формата (D-06, D-22).
- Не править факты в `docs/research/` без новой даты и источника.
- Не отключать, не пропускать и не ослаблять тесты и проверки ради
  зелёного прогона.
- Не добавлять workflow GitHub Actions и не запускать их (D-23).

## Документы

Документ обновляется в том же изменении, что и код, который он
описывает: новый модуль — `ARCHITECTURE.md` (таблица §2), новое поле
формата — `CONFIG_FORMAT.md` и новая версия формата, новая угроза —
`SECURITY_MODEL.md`, новая зависимость — матрица и PROVENANCE. Ссылки
на решения, документы, разделы и этапы проверяют `docs.links` и `docs.refs`.
Раздел «Прогресс» в `README.md` не правится руками: его строит
`tools/hostcheck/readme_progress.py` из плана, решений и `TODO.md`.
