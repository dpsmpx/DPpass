# Обзор безопасности перед выпуском 0.7.48

Дата: **31 октября 2026**. Срез: `main` DPmetaApp после D-105
(приложение 0.7.48-dev, код 118; ПК 0.1.27-dev; ядро Xray 26.9.30). Цель —
этап 5, работа 7 (`docs/direction/ROADMAP/05-release.md`): пройти модель
угроз (`docs/SECURITY_MODEL.md`) по пунктам T1–T18 и записать, что
осталось. Выбор автора в форме 31.10.2026 — «Обзор безопасности».

## 1. Предмет и метод

Проверялось для каждой угрозы:
- есть ли у меры работающая проверка — тест, шаг DP Verify или проверка
  на устройстве в `TODO.md`;
- не расходятся ли с мерой код и решения, принятые после аудита 0.5.0
  (`docs/audits/SECURITY_STABILITY_AUDIT_0.5.0.md`): D-48…D-105, в том
  числе ПК на Linux (D-74…D-87) и Windows (D-97…D-102);
- что остаётся и почему.

Как:
- полный прогон `tools/hostcheck/run.sh --full` (35 проверок) и полная
  проверка DPmetaApp (21) — зелёные на этом срезе;
- воспроизводимость APK — две сборки, вторая с нуля (D-105);
- чтение кода мест, которые модель называет мерами: буфер обмена,
  привязка сокетов на Windows, политика моста, загрузка библиотек COM.

Не проверялось здесь: работа на устройствах. Телефон, ПК с Linux и
Windows — пункты `TODO.md` («На устройстве», «Linux — этап 6», «Windows —
этап 7»). Облачная сессия Windows не запускает, а Wine не заменяет
настоящих прав NTFS, UAC, Wintun и WFP.

## 4. Находки

**F-1 (средняя) — история буфера обмена Windows.** Кнопки «Скопировать»
вкладки «Раздача» и окна локального прокси, а также копия «Журнала»
кладут текст в буфер обмена через AWT (`StringSelection`). На Windows
такой текст попадает в историю буфера (Win+V), если она включена, и в
облачный буфер, если включена синхронизация. Пароль останется там и уйдёт
на другие устройства пользователя. У Windows для этого есть
зарегистрированные форматы: `ExcludeClipboardContentFromMonitorProcessing`
не пускает данные ни в историю, ни в облако; `CanIncludeInClipboardHistory`
и `CanUploadToCloudClipboard` со значением 0 — по отдельности (Microsoft,
«Clipboard Formats», раздел «Cloud Clipboard and Clipboard History
Formats», `docs/research/WINDOWS_SHELL.md`, §8). На Android
DPpass ставит пометку «чувствительное» (Android 13+, D-47).
**Исправлено:** на Windows «Скопировать» и «Копировать журнал» кладут
вместе с текстом все три формата со значением 0 (`SecretClipboard`). Имена
форматов DPpass сопоставляет видам данных в карте AWT (`SystemFlavorMap`),
и AWT на Windows регистрирует их сам. На Linux таких форматов нет — там
только текст. **Проверка:** `SecretClipboardTest`; что Win+V и облачный
буфер текст DPpass не видят — на ПК автора (`TODO.md`).

**F-2 (документ) — T4 на Windows.** Модель говорила: «проверка сети при
поднятом туннеле — отказ с причиной». С D-99 пробы под туннелем привязаны
к интерфейсу мимо адаптера, а с D-102 сокеты ядра в сеансе через
устройство раздачи — к его сети. Исправлено.

**F-3 (документ) — T8.** Модель называла режим без `VpnService`
«отложенным решением». Он есть с D-95: локальный прокси на 127.0.0.1 с
паролем, без `TRANSPORT_VPN`. Исправлено.

**F-4 (документ) — T18.** Модель говорила: «входы ядра — только loopback с
паролем». С D-101 на Windows есть и вход раздачи с паролем на адресах
точки доступа. Исправлено.

**F-5 (документ) — шапка и §6.** Срез модели был датирован 6 октября
(0.5.0), а в таблице «Как проверяется» не было проверок ПК. Шапка
обновлена, строки для ПК добавлены. В T3 записана F-1 и её исправление.
