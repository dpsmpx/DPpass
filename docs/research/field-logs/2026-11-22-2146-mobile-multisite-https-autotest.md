## Инженерная гипотеза и внедрённое изменение

В исходной AUTO-ротации первые две новые TCP-сессии по одному SNI пробовали `split-1`, затем `split`. Обе стратегии получили 0/2 для YouTube HTML. Успешные `tlsrec-split` и `fake-5` находились позже в списке кандидатов; текущий 48-запросный диагностический тест сам по себе раньше **не обучал AUTO** по подтверждённым HTTP-результатам.

Добавлено временное обучение `www.youtube.com` только после *двух* baseline-отказов и *двух* валидных HTML-ответов одной стратегии. По этим данным предпочтительна `tlsrec-split` (пара 934+1118 быстрее 1202+1474 для `fake-5`). Стабильность подтверждается только после **повторного настоящего тестирования на телефоне**, не самим коммитом. IP и другие хосты не наследуют этот вывод; при двух неудачных live-подключениях предпочтение сбрасывается. Сеть/переподключение тоже сбрасывают обучение.
