# DPpass: выбор пути и генерация локальных нейромоделей

## Главный экран

Под основной кнопкой подключения реализован явный переключатель:

- **VPN-сервер** — подключение к подписке через штатный Xray, конкретный сервер либо пункт «Автоматически» в списке серверов. Указанная подписка и пароль не меняются.
- **Стратегии** — экспериментальный Zapret2 через Android VpnService, прямые соединения без внешнего VPN-сервера, локальный выбор стратегий.

Переключатель меняет реальный backend `Zapret2Backend.OFF` / `VPN_SERVICE` в настройках и вызывает стандартное переподключение, если VPN уже поднят. Выбор подписки не стирается. Root-ветка остаётся в расширенных настройках; этот переключатель никогда не получает root автоматически.

## Две независимые генеративно инициализированные нейромодели

**Не поставляются в APK и не скачиваются.** Пользователь нажимает «Создать модель» и выбирает **32, 128 (по умолчанию), 512 или 1024** скрытых нейрона. Код inference реализован внутри APK, а начальные **числовые веса** генерируются криптографическим генератором случайных чисел локально, без обучения на сторонних данных. Увеличение размера не гарантирует улучшения — крупная модель требует больше вычислений. Файлы хранятся в частном хранилище, ограничены 1 МиБ и проверяются по размерности, формату и допустимым значениям. Есть возможность удалить/пересоздать. Никакого запроса к внешнему ИИ или отправки данных подключения нет.

**Стратегии Zapret2 (8×H×9, Go/JNI).** Входы: тип TLS/HTTP/QUIC, IPv6, наличие домена, класс Googlevideo CDN, мобильная сеть/Wi-Fi. По умолчанию используется встроенная адаптивная эвристика, даже без модели. При созданной модели — MLP предлагает кандидатов новых соединений, но проверенное предпочтение для конкретного хоста остаётся сильнее. Обучение ограниченным SGD на сигнале *реально полученного* downstream, а не на случайном факте TCP dial; короткие ответы не подтверждают работоспособность видео. Обучение только в памяти процесса; при смене сети временная нейромодель загружается заново из исходного локально созданного файла.

**Автоматический VPN-сервер (8×H×1, Kotlin).** Входы берутся из существующего DPpass Core: измеренная задержка или неизвестное значение, состояние здоровья, число отказов, последний успешный сервер, давность успеха, транспорт UDP/QUIC, тип физической сети, исходное место в плане. Штатный `CandidatePlanner` **сначала** исключает недоступные/несовместимые/backoff-серверы и назначает базовый приоритет; ML допускается только при выбранном в списке серверов пункте **«Автоматически»**, без ручного закрепления. Модель может переставить только соседних пригодных кандидатов с одинаковым классом здоровья, после хотя бы четырёх реальных попыток с обратной связью. Опыт поступает из `ConnectionOrchestrator` после проверенного успеха или отказа; ошибки локального ядра не выдаются за провал сервера. Обученные веса и **только числовой счётчик** попыток хранятся локально; серверные ID, подписки, URL, IP, исходные примеры и ключи в файл модели не записываются. После явного выбора одного сервера ML не вмешивается.

Обе нейросети — **экспериментальные модели с локальной случайной инициализацией**, а не доказанно предобученные «оптимальные» сети. Начальная пригодность определяется существующими безопасными эвристиками. Необходимо накопить реальные данные; сравнение с базовым автоопределением требует полевых испытаний.

## Выпуск и ограничения

Сборка: Android ARM64, Alpine/PRoot + JNI, `versionCode=133`, `0.7.55-dev`. CI собирает как отдельный debug `com.dpsmpx.dppass.alpine`, так и оптимизированный `assembleRelease` пакет `com.dpsmpx.dppass`, подписанный известным **экспериментальным alpha-сертификатом** SHA-256 `c18792812566ca4a18b518d51313515ff2d62bf8299446e99943eeb5d0630d11`. Это **не магазинный производственный ключ**; обновление существующего пакета возможно только при совпадающей подписи. Проверяются Go/JVM/Android, R8 APK, ARM64 ELF/PRoot, отсутствие весов в APK, версия против последней опубликованной alpha и фактический сертификат.

Результаты реального мобильного полевого отчёта от 22.11.2026 23:11 +03:00, **до данного выпуска**: Google HTML 16/16, YouTube HTML 8/16 (AUTO 2/2), YouTube API HTTP transport 0/16 (все timeout), JPEG thumbnail 15/16. В агрегированных замерах 825 `tcp_dial_unreachable`, **все IPv6**, при 116 успешных IPv4 dial и 0 успешных IPv6 dial. Отсутствие рабочего IPv6-маршрута вероятно объясняет эту часть ошибок; это **не подтверждает** решение проблемы YouTube API или видео. Локальный DPI-алгоритм не может создать несуществующий IPv6 маршрут; нужны дополнительные проверки IPv4/IPv6 DNS и CDN.

## Обязательные испытания на телефоне

1. Установить подписанную release-сборку поверх прежней подписанной alpha с **тем же** сертификатом; при иной подписи ничего не удалять — использовать отдельную debug APK и импортировать подписку вручную.
2. На главной выбрать «VPN-сервер», в списке серверов — «Автоматически», убедиться, что подписка не исчезла и штатная схема работает **без** ML.
3. Создать модель выбора серверов **128 нейронов**, подключить, проверить реальный план и несколько переподключений/отказов, затем повторить с 512. Проверить, что ручной сервер не меняется автоматически.
4. Перейти в «Стратегии», создать/удалить отдельную MLP стратегий и сравнить результаты с безмодельным AUTO, в том числе по YouTube API, ленте, видео и ошибкам IPv6.
5. Проверить откат/повторное подключение, изменения мобильной/Wi-Fi сети, отсутствие скачивания модели и выход за лимиты по памяти/размеру.

Пока физические испытания не получены, **не утверждать улучшение выбора серверов, успешную работу YouTube или готовность релиза для всех устройств**.
