# Разбиение пакетов и десинхронизация против DPI: что применимо в DPpass

Дата исследования: **18 октября 2026**. Вопрос автора (18.10.2026):
реализовано ли в DPpass разбиение пакетов, как в Zapret, Zapret 2 и
ByeByeDPI. Документ — факты для решения; само решение — за автором
(`TODO.md`, «Решения автора»; `docs/direction/DECISIONS.md`, «Отложено»,
строка «Локальная DPI-десинхронизация»). Код других проектов не берётся,
только сведения о подходах (`docs/direction/RESEARCH_SCOPE.md`, §3,
правило 5; D-20). Метки качества источников — A–E
(`docs/research/RUSSIA_NETWORK_RESTRICTIONS.md`, §0).

## 1. Коротко

- **В DPpass 0.7.23-dev разбиения нет**: ни для соединения с сервером, ни
  для прямого трафика. Директивы подписки `fragmentation-*` и `noises-*`
  распознаются как управляющие и не применяются: подписка не меняет
  поведение клиента без согласия пользователя (D-11, `Metadata.kt`).
- **Ядро, которое уже в APK, это умеет.** Xray 26.9.30 — разбиение TLS
  ClientHello на записи и TCP-сегменты (`fragment`) и шум перед UDP
  (`noises`), §3. Root не нужен: сокеты ядра — собственные сокеты
  процесса DPpass.
- **Чего ядро не умеет.** Поддельные пакеты с малым TTL, перестановку
  частей и срочные данные (OOB), как у byedpi и ByeByeDPI. Это была бы
  своя реализация в мосте ядра (§5, вариант 4).
- **Действенность не обещается** (D-13). Единственное измерение уровня A
  про ТСПУ (март 2025) касается одного правила — блокировки ECH: разбиение
  только на сегменты или только на записи не помогло, оба вместе —
  помогло (§4).

## 2. Как устроены Zapret, Zapret 2, byedpi и ByeByeDPI

| Проект | Как получает трафик | Root на Android | Приёмы | Лицензия, источник |
|---|---|---|---|---|
| **Zapret** (bol-van) | `nfqws` — пакеты из NFQUEUE (Linux) или WinDivert (Windows); `tpws` — прозрачный прокси | нужен: правила iptables/nftables | поддельные пакеты, разбиение и перестановка сегментов, TTL, контрольные суммы | MIT; `docs/research/ZAPRET_ADAPTIVE_METHODS.md` (05.10.2026) |
| **Zapret 2** (bol-van, `nfqws2`) | то же, стратегии — на Lua | нужен: на Android — модули Magisk и KernelSU (руководства сообщества, C) | те же, плюс оркестратор `circular` | там же; руководство publish.obsidian.md/zapret, прочитано 18.10.2026 |
| **byedpi** (hufrea) | локальный SOCKS-прокси, есть прозрачный режим (`-E`): меняет **свои** исходящие соединения | не нужен для своих сокетов | `--split`, `--disorder`, `--oob`, `--disoob`, `--fake` (с `--ttl`, `--md5sig`), `--tlsrec`, `--tlsminor`, `--mod-http`, `--udp-fake`, `--drop-sack`; `--auto` — группы с признаками `torst`, `redirect`, `ssl_err` | MIT; README, прочитан 18.10.2026. По README `--md5sig` — только Linux и может быть выключен в ядре Android; `--drop-sack` — только Linux |
| **ByeByeDPI** (romanvht) | приложение Android: запускает byedpi в процессе и заводит в него трафик через режим VPN (`hev-socks5-tunnel`) или работает прокси | о root README не говорит; работа через `VpnService` его не требует | приёмы byedpi | README, прочитан 18.10.2026; «ничего не передаёт на удалённый сервер» |

Уточнение к `docs/research/ZAPRET_ADAPTIVE_METHODS.md`, §5 (05.10.2026, «нужен
доступ к пакетам до ядра сети (root)»): root нужен приёмам над **чужими**
пакетами (Zapret). Приёмам над собственными соединениями процесса он не
нужен — так работают byedpi и ByeByeDPI, так же устроено ядро DPpass
(`docs/research/ALLOWLIST_ACCESS.md`, 17.10.2026).

## 3. Что есть в ядре DPpass

Источник — исходники Xray-core закреплённой версии: `go.mod` →
`github.com/xtls/xray-core v1.260327.1-0.20260930074004-b26a91de4f32`,
`xray version` → «Xray 26.9.30». Файлы `infra/conf/freedom.go` и
`proxy/freedom/freedom.go`, прочитаны 18.10.2026.

- **`fragment` у исходящего `freedom`** (прямое соединение):
  - `packets: "tlshello"` — первая запись TLS соединения (тип 22,
    ClientHello) разбивается на несколько записей TLS длиной из диапазона
    `length`. При `interval` больше 0 каждая запись пишется в сокет
    отдельно, с паузой из диапазона, — это отдельные TCP-сегменты. При
    `interval: 0` записи уходят одним куском: разбиение только на записи
    TLS. `maxSplit` ограничивает число частей;
  - `packets: ""` — разбиение на TCP-сегменты всех записей соединения;
    `packets: "1-3"` — только записей с первой по третью;
  - `length` и `interval` обязательны, нижняя граница `length` не 0:
    иначе ядро не принимает конфигурацию.
- **`noises`** — только UDP: перед первым пакетом соединения уходит шум
  (`rand` — случайные байты длиной из диапазона, `str`, `hex`, `base64`) с
  задержкой `delay`; к порту 53 не применяется.
- **К соединению с сервером** приём применяется через
  `streamSettings.sockopt.dialerProxy`: соединение исходящего `proxy`
  открывается через `freedom` с `fragment`.
- **Компилятор DPpass** (`XrayCompiler`) сейчас не пишет ни `fragment`,
  ни `noises`, ни `dialerProxy`.

**Наблюдение на хосте** (собственный замер DPpass, 18.10.2026; только
127.0.0.1, внешней сети нет). Xray 26.9.30 — вход SOCKS, выход `freedom`. Через
него `curl` открывает TLS к локальному приёмнику, а тот записывает, какими
кусками пришли байты и как разложены записи TLS:

| `fragment` | Куски на приёмнике | Записи TLS в ClientHello |
|---|---|---|
| нет | 1 кусок, 517 байт | 1 запись, 512 байт |
| `tlshello`, `length` 20–40, `interval` 5–10 мс | 18 кусков за ~135 мс | 18 записей по 14–39 байт |
| `tlshello`, `length` 20–40, `interval` 0 | 1 кусок, 592 байта | 16 записей по 19–39 байт |

`xray run -test` принимает конфигурацию с `fragment`, `noises` и
`dialerProxy` и отвергает её при `length` с нижней границей 0.

Разбиение ClientHello на записи допускает сам протокол: сообщения
рукопожатия могут занимать несколько записей (RFC 8446, §5.1). Примет ли
так сервер REALITY и промежуточные узлы на пути, на хосте не проверено.

## 4. Что известно о действенности в России

- **A** — Niere, Lange, Heitmann, Somorovsky, «Encrypted Client Hello (ECH)
  in Censorship Circumvention», FOCI 2025. Измерения — март 2025, точка в
  России. ТСПУ сбрасывает ClientHello с расширением ECH и именем
  `cloudflare-ech.com`, и только к адресам Cloudflare.
  - Только разбиение на TCP-сегменты не помогло, только разбиение на
    записи TLS — тоже. Авторы пишут о «новых возможностях сборки» потока
    у ТСПУ, в отличие от более ранней работы Xue и др. (IMC 2022).
  - Оба приёма вместе помогли.
  - Это одно правило (ECH), не список запрещённых имён вообще. `tlshello`
    с паузой из §3 — как раз оба приёма вместе.
- `docs/research/RUSSIA_NETWORK_RESTRICTIONS.md`, L2: разбиение ClientHello
  «работает против части реализаций, не гарантированно».
- **C/D** — сообщения о том, что фильтр выучивает параметры приёмов по
  умолчанию. Например, сбой GoodbyeDPI по сообщению «Вёрстки»; год в
  статье не указан. Параметры устаревают, и их подбирают заново
  (`--auto` у byedpi, `circular` у Zapret 2).
- **Измерений 2026 года** для byedpi и ByeByeDPI на мобильных сетях в
  открытых источниках не найдено (поиск 18.10.2026).
- **Где не помогает по устройству:** блокировка по адресу (L3, L4) и белый
  список по адресу (L9). Пакет к закрытому адресу не проходит, как его ни
  режь (`docs/research/ALLOWLIST_ACCESS.md`).

## 5. Что применимо к DPpass — варианты для решения

| № | Вариант | Что делает | Против чего (свойство, не обещание) | Цена и риски | Что меняется в DPpass |
|---|---|---|---|---|---|
| 1 | Разбиение ClientHello **к серверу** | `fragment` `tlshello` с паузой через `dialerProxy` у серверов TCP + TLS/REALITY | правила L2 по имени или ClientHello к серверу, если фильтр не собирает поток | крошечные записи TLS — сами по себе редкий признак (L5); +100–150 мс к рукопожатию; REALITY с разбиением не проверен | компилятор и параметр профиля или глобальный, по умолчанию выключено (D-05); вариант кандидата в плане и опыт по сети (D-15, D-44) |
| 2 | Разбиение для **прямого** трафика к выбранным сайтам, без сервера — как ByeByeDPI | правило маршрутизации «напрямую с разбиением» → `freedom` с `fragment` | L2 по имени для сайтов с открытым адресом | режим без сервера (TUN + ядро только с прямыми выходами) — новое для DPpass; новое действие правила — новая версия формата (D-06) | `CONFIG_FORMAT.md`, `RouteEvaluator`, компилятор, интерфейс правил |
| 3 | Шум перед UDP | `noises` у прямого UDP | правила по первому пакету UDP (QUIC Initial по имени — L2) | к UDP-транспортам сервера (Hysteria2) через `dialerProxy` не проверено | как вариант 2 |
| 4 | Своя десинхронизация в мосте Go | поддельная часть с малым TTL, перестановка частей — `setsockopt(IP_TTL)` на своих сокетах, root не нужен | фильтры, собирающие поток, но не отличающие подделку | своя сетевая логика под ядром; риск рвать соединения; нужна методика замера | мост ядра (D-25), тесты на хосте с локальным приёмником; свой код по публичным описаниям (D-20) |
| 5 | byedpi зависимостью | второй сетевой движок в процессе, C | как у byedpi | нативный код вне моста запрещён (`code.forbidden`, D-25); матрица лицензий, D-18 | не рекомендуется |

Как проверять любой выбранный вариант:
- **На хосте:** эталоны компилятора и `xray run -test` (`project.xray`);
  локальный приёмник, как в §3, — тест, что ClientHello уходит частями.
- **На телефоне:** А/Б-сравнение — тот же сервер с разбиением и без, в
  одной сети. Исходы — в «Почему этот сервер». Чужую инфраструктуру и
  системы фильтрации не зондировать (`docs/direction/RESEARCH_SCOPE.md`, §4).
