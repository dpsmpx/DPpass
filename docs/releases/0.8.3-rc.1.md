# DPpass 0.8.3-rc.1 (ARM64)

Release candidate, not a declaration of completed physical acceptance.

- Version code 157, stable application ID com.dpsmpx.dppass, previously pinned direct-distribution signer.
- Zapret2 root: original pinned upstream nfqws2 v1.0.7 and Lua runtime, IPv4/IPv6 NFQUEUE, TCP and optional QUIC; root/kernel/SELinux prerequisites apply.
- Zapret2 no root: existing DPpass protected-socket planner, including Alpine if selected. This is NOT upstream nfqws2 and cannot offer full NFQUEUE/raw-packet capabilities without privileges.
- ByeDPI VPN: original upstream ciadpi v0.17.3, commit 7efde1b1296eaaa187b70e951894dde17527489c, built from pinned source with Android NDK, loopback SOCKS TCP/UDP, private same-UID socket protection bridge, DNS resolved in Xray (no-domain in ciadpi). The local SOCKS listener is unauthenticated and loopback-only; random port is not authentication.
- ByeDPI root: original ciadpi transparent mode, TCP 80/443, IPv4 OUTPUT REDIRECT and an additional IPv6 listener/REDIRECT if IPv6 NAT is available, daemon root UID excluded, dedicated cleanup/watchdog. Transparent upstream does not handle UDP; IPv6 support depends on the device. No claim of transparent UDP support.
- No remote service is needed for local modes; subscription path and key are unchanged.
- Dashboard from 0.8.3-dev retained; ByeDPI RTT/Jitter deliberately unavailable until original engine socket measurements are implemented. Loopback RTT is not internet RTT.
- CI verifies source pin, ELF, packaged source/license and digest, package and signing identity. Device testing still required: real VPN TCP/UDP protection, root firewall rollback, IPv6, no DNS leak, lifecycle, Android/SELinux variations and actual site playback. Existing native diagnostics remain Zapret2-specific.

Full upstream Zapret2 on stock non-root Android is not an available mode. Do not call the compatible adapter full upstream support.
