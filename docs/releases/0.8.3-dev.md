## Candidate changes and limits
- Live AUTO starts with untouched TCP/UDP and records per-host/peer/protocol
  reachability; a response is not verified application content. Plain successes
  take precedence over opportunistic strategies for that peer.
- Unmatched interception defaults to off; explicit stored opt-in is respected.
  Force TCP is scoped to selected hosts in AUTO when the list is nonempty;
  an explicitly enabled global setting with an empty hostlist remains global.
- Repeated ENETUNREACH on experimental literal IPv6 TCP dials triggers a
  15-second cooldown. Other errors, IPv4 and subscription transport unaffected.
- DPTS records H1/H2 verified HTML, per-IP evidence and verified transport
  separately. Two distinct IPs with three verified HTML responses each, the same
  HTTP protocol and failed plain controls are required for global HTML learning.
  The optional fixed 3×6 verified HTML calibration is separate from the passive
  MLP; existing models and parameter budgets survive. API failures and handshake
  successes are never labelled verified content.
- Main screen: trailing ~5-second average of real terminal direct/proxy counters;
  provider usage accounting remains proxy-only. Mean kernel TCP RTT and RTTVAR
  from at most 32 established TCP sockets, refreshed every two seconds with the
  screen on, no traffic generation. They measure outbound TCP peers, not ICMP,
  end-to-end site latency through a VPN server, or UDP jitter. Missing samples
  show a dash. This is a bounded sample, not an exhaustive flow census.
