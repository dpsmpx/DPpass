# Процесс DPpass

Как в DPpass делается изменение, чем оно проверяется и как
обновляются зависимости. Короткая версия правил — `CLAUDE.md`.

## 1. Порядок изменения

1. **Решение раньше кода.** Найти решение, которое изменение
   затрагивает (`docs/direction/DECISIONS.md`), и раздел
   `docs/ARCHITECTURE.md` про модуль. Изменение, которое противоречит
   решению, начинается с нового решения D-NN (следующий свободный номер
   — в шапке журнала), а не с кода.
2. **Задача в рамках этапа.** Этап меняет только то, что в нём
   записано (`docs/direction/ROADMAP/README.md`); найденное «заодно» —
   строка в `TODO.md`, а не правка.
3. **Код, тест и документ — вместе.** Новый модуль — таблица §2 в
   `docs/ARCHITECTURE.md`; новое поле формата — `docs/CONFIG_FORMAT.md` и
   новая версия формата; новая угроза — `docs/SECURITY_MODEL.md`; новый
   предел — `docs/PERFORMANCE_BUDGET.md`; новая зависимость — §3 ниже.
   Сменилось состояние этапа, критерий выхода, решение или пункт
   `TODO.md` — `python3 tools/hostcheck/readme_progress.py` обновляет
   раздел «Прогресс» в `README.md` (руками его не правят).
4. **Новый баг — новый файл корпуса** `tests/data/` (`docs/TESTING.md`,
   «Корпус регрессий»); новый код диагностики — строка в
   `tools/hostcheck/diag_codes.txt` (D-22).
5. **hostcheck зелёный** (§2) — только тогда изменение готово.
6. **PR** — в `main`; описание: что сделано, что осталось, что найдено
   и записано в `TODO.md`; итог полного прогона hostcheck (§4).

## 2. Проверки

### Запуск

```sh
tools/hostcheck/run.sh            # всё, что можно на этой машине; пропуск — громко, но не ошибка
tools/hostcheck/run.sh --quick    # только быстрые проверки (без Gradle), секунды
tools/hostcheck/run.sh --full     # перед слиянием (§4): пропуск (нет Android SDK) — ошибка
```

Код возврата: 0 — всё прошло (в обычном режиме — кроме названных
пропусков), 1 — хотя бы один шаг упал, 2 — неверный вызов. Вывод каждого
шага — `build/hostcheck/<шаг>.log`; на экран — итоговые строки `✓`, а
при отказе — хвост журнала.

### Шаги

| Шаг | Что ловит | Решения |
|---|---|---|
| модули — `tools/hostcheck/check_modules.py` | модули и направления зависимостей не по таблице `docs/ARCHITECTURE.md`, §2; `android.*` вне `app/`; модель сети и фиктивное ядро не на своих местах | D-02, D-03 |
| запрещённые API — `tools/security/check_forbidden_apis.py` | DNS мимо туннеля, `reveal()` вне разрешённых мест, стек исключения, печать вне `cli/`, системное время, слабая случайность и криптография, свои `TrustManager`, `android.util.Log`, сон и `runBlocking`, «/*» внутри комментария (в Kotlin — вложенный комментарий) | D-11, D-21, D-22 |
| секреты — `tools/security/check_secrets.py` | файлы ключей, закрытые ключи, токены, ссылки прокси на настоящие адреса, несинтетические UUID — и в открытом виде, и внутри base64 | D-11, D-20 |
| корпус — `tools/hostcheck/check_fixtures.py` | непарные файлы корпуса, нестрогие ожидания, несуществующие коды и условия сети, реестр кодов, несинтетические данные (и в base64-телах подписок) | D-05, D-22 |
| ссылки — `tools/hostcheck/check_docs.py` | ссылки на несуществующие документы, разделы, решения, угрозы, этапы и тесты | все |
| зависимости — `tools/provenance/check_dependencies.py` | зависимость или версия без строки в матрице лицензий и PROVENANCE, координаты мимо каталога, чужие репозитории, несверенный Gradle, незаписанный двоичный файл; модуль Go ядра (`tools/xray/go.mod`) без строки или с другой суммой `go.sum`, Xray не той версии, что в каталоге, `replace` | D-12, D-18, D-20, D-24 |
| манифест — `tools/hostcheck/check_manifest.py` | неутверждённые разрешения, резервные копии, открытый HTTP, лишний экспорт компонентов | D-17, D-19 |
| README — `tools/hostcheck/readme_progress.py --check` | раздел «Прогресс» в `README.md` отстал от плана, критериев выхода, решений, `TODO.md`, аудитов; противоречия между ними (этап «выполнен» при открытых критериях, разное состояние в плане и в файле этапа) | — |
| формат — `tools/hostcheck/check_format.py` | не UTF-8, CR/CRLF, нет перевода строки в конце, хвостовые пробелы, табуляции, невидимые и двунаправленные символы (Trojan Source); корпус не проверяется | — |
| сборка и тесты ядра — `./gradlew build :cli:installDist` (с Android SDK — `-x :app:build`: APK собирается шагом Android) | ошибки и **предупреждения** компилятора (они — ошибки), модульные и межмодульные тесты, корпус, fuzz | D-05 … D-22 |
| cli smoke — в `run.sh` | весь конвейер через оболочку JVM: 15 сценариев, коды выхода, вывод, секреты не печатаются | D-11, D-21 |
| Xray — `tools/xray/check_xray.py` | эталон компилятора, который Xray закреплённой версии не принимает (`xray run -test`); решение маршрутизации Xray, не совпавшее с `RouteEvaluator`; собранное ядро не той версии, что в каталоге (`docs/TESTING.md`, «Эталоны Xray») | D-05, D-09, D-24 |
| Xray: мост и JNI — `tools/xray/native.py host` и `:tests:integration:xrayJniTest` | `go vet` и `go test` моста ядра в обеих сборках (с тестовым входом и без); библиотека для JVM хоста, экспорт JNI которой не совпал с `external` объекта `XrayJni`; нарушение договора JNI в JVM хоста — версия, проверка, один экземпляр, защитник сокетов, счётчики (`docs/TESTING.md`, «Мост Xray и JNI») | D-25 |
| Xray: геоданные — `tools/xray/geodata.py --test` | `go vet` и `go test` сборщика набора геоданных; источник, чья сумма не совпала с PROVENANCE (DB-IP — файл в репозитории, dlc — Go-модуль со сверкой sum.golang.org); строка источника, которую сборщик не понял; код собранного набора, который ядро Xray не загрузило (`docs/TESTING.md`, «Набор геоданных») | D-27, D-31 |
| Android: сборка и Lint — `:app:build :app:lint` (нужны Go и NDK) | сборка APK вместе с `libdppassxray.so` трёх ABI (задачи `xrayNative<Вариант>` → `tools/xray/native.py android`) и набором геоданных (задачи `xrayGeodata<Вариант>` → `tools/xray/geodata.py`); Lint с `warningsAsErrors`, и для модулей ядра (`checkDependencies`) | D-17, D-25 |
| Android: API ядра ≤ minSdk — `tools/hostcheck/check_android_api.py` | вызовы Java API в модулях ядра, которых нет на Android 8.0 (Lint их в JVM-модулях не видит) | D-02, D-17 |
| Android: APK — `tools/hostcheck/check_apk.py` | в собранном APK: разрешения и компоненты из зависимостей в итоговом манифесте, код не из утверждённых корней пакетов (SDK телеметрии и прочее чужое); нативный код — не ровно `libdppassxray.so` трёх ABI (`arm64-v8a`, `armeabi-v7a`, `x86_64`), сжатая библиотека, смещение в zip или сегменты ELF не выровнены по 16 КБ, нет экспорта JNI; набор геоданных не по своему оглавлению (файлы, SHA-256, сжатие, атрибуция DB-IP), не из источников каталога или не тот, что собрал шаг «Xray: геоданные»; APK одного ABI больше предела (`docs/PERFORMANCE_BUDGET.md`, §4) | D-12, D-17, D-20, D-25, D-27, D-28 |

Быстрые шаги (первые девять) работают без сборки и без сети — их стоит
запускать перед каждым коммитом (`--quick`).

### Окружение

| Что | Версия | Зачем |
|---|---|---|
| JDK | 21 | инструменты сборки (`jvmToolchain(21)`); байт-код — Java 17 |
| Python | 3.11 или новее | скрипты `tools/` (`tomllib`) |
| Go | 1.21 или новее (нужную версию toolchain — `go1.27.1` — он скачивает сам по `tools/xray/go.mod`) | шаги «Xray», «Xray: мост и JNI» и «Xray: геоданные»: сборка ядра, `dppass-xray-probe`, библиотеки `libdppassxray` и набора геоданных; без Go шаги пропускаются, а `--full` падает |
| Компилятор C и заголовки JNI | `cc` (gcc или clang) для cgo; `jni.h` из JDK (`JAVA_HOME/include`) | библиотека моста для JVM хоста (`native.py host`) |
| Android SDK | платформа 36 (`compileSdk`) и build-tools (`aapt2`, `dexdump`), путь — `ANDROID_HOME` или `sdk.dir` в `local.properties` | модуль `app`, `check_android_api.py`, `check_apk.py`; без SDK `app` не подключается, а `--full` падает |
| Android NDK | версия из `gradle/libs.versions.toml` (`android-ndk`, сейчас `30.0.16248370`) в `$ANDROID_HOME/ndk/<версия>`; ставится `sdkmanager "ndk;30.0.16248370"` | сборка `libdppassxray.so` для APK (D-25); без NDK (или без Go) шаги Android пропускаются, а `--full` падает |
| Сеть | при первом запуске | Gradle скачивает дистрибутив (сверяя SHA-256) и зависимости из Maven Central и Google Maven; Go — toolchain и модули с proxy.golang.org (сверяя с `go.sum` и sum.golang.org) |

### Правила

- **Падающая проверка не ослабляется.** Тест и проверку чинят или
  меняют вместе с решением; отключить, пропустить, поднять порог «чтобы
  прошло» нельзя (`CLAUDE.md`, «Чего не делать»).
- **Исключение — с причиной и в одном месте:** `tools/security/secrets_allow.txt`,
  `tools/hostcheck/android_api_allow.txt`, разрешённые места в самих
  скриптах. Исключение без причины — ошибка обзора.
- **Пропуск — громкий.** Шаг, который нельзя выполнить на этой машине,
  называется в итоге как пропущенный; в `--full` пропуск —
  ошибка.
- **Новая проверка доказывает себя:** до включения в `run.sh` она
  должна поймать намеренно внесённое нарушение и пройти на чистом коде.

## 3. Зависимости

Чек-лист D-18 — для новой библиотеки, плагина, новой версии, Gradle,
а с этапа 2 — и ядра прокси. Обновление делается не
«потому что вышло», а по причине: исправление уязвимости, нужная
возможность, требование платформы.

1. **Причина** — в описании изменения.
2. **Журнал изменений** между версиями прочитан: ломающие изменения,
   изменения поведения по умолчанию, новые сетевые обращения и сбор
   данных (D-12).
3. **Лицензия** по POM (или `LICENSE` на закреплённом коммите) той
   версии, что берётся; смена лицензии — остановка и пересмотр строки
   матрицы, а не обновление молча.
4. **Каталог** — версия только в `gradle/libs.versions.toml`;
   координат и версий плагинов мимо каталога нет.
5. **Записи** в том же изменении: строка в `docs/legal/THIRD_PARTY_MATRIX.md`
   (лицензия, куда попадает, статус) и в `docs/PROVENANCE.md` (откуда,
   как проверено, дата).
6. **Gradle**: `./gradlew wrapper --gradle-version X --distribution-type bin
   --gradle-distribution-sha256-sum <сумма>`, где сумма — из
   `services.gradle.org/distributions/gradle-X-bin.zip.sha256`; SHA-256
   нового `gradle-wrapper.jar` сверяется с `gradle-X-wrapper.jar.sha256`;
   обе суммы — в `docs/PROVENANCE.md`, §3.
7. **Ядро прокси** (D-24): новая версия — в каталоге (`xray`,
   `xray-go-module`) и в `tools/xray/go.mod` (`go get` версии upstream,
   затем `go mod tidy`; `go.sum` — только так, не руками); каждый
   модуль `go.mod` — строка матрицы (лицензия — по файлу в архиве
   модуля) и PROVENANCE (версия и сумма `h1:` из `go.sum`);
   `capabilityDiff` старой и новой матрицы возможностей — в описании
   изменения; эталоны перезаписаны (`docs/TESTING.md`, «Эталоны Xray»)
   и их разница просмотрена; шаг «Xray» зелёный.
8. **Полный прогон**: `tools/hostcheck/run.sh --full` зелёный,
   корпус и fuzz — без новых находок.

## 4. Перед слиянием

CI нет: GitHub Actions в DPpass не используется и не запускается
(D-23), workflow в `.github/workflows/` не добавляются — шаг
«зависимости» считает их ошибкой. Ничего не ждёт «зелёного CI».

Условие слияния в `main`:

1. `tools/hostcheck/run.sh --full` выполнен **локально** на последнем
   коммите PR, на машине с JDK 21, Python 3.11+ и Android SDK (§2,
   «Окружение»), и прошёл.
2. Итог прогона — строки `hostcheck (full):` из вывода — в описании PR,
   с коммитом, на котором он сделан.
3. Если Android SDK нет, прогон частичный и так и называется; слияние —
   после полного прогона, а не вместо него.

Правила, которые остаются в силе без CI:

- **Gradle тот же у всех:** через wrapper с проверкой SHA-256
  дистрибутива; `gradle-wrapper.jar` сверяет с PROVENANCE шаг
  «зависимости».
- **Сборка ничего не отправляет:** без сканов сборки и сервисов
  аналитики (D-12; `org.gradle.welcome=never` в `gradle.properties`).
- **Красный прогон — работа этого изменения**, а не повод повторить
  его «на удачу»: повтор — только если шаг умер до тестов (загрузка,
  нехватка места).
