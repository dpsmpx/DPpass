# A6/A7 — DPTS: сопоставимость обучения

Дополнение к [плану локального ядра](LOCAL_DPI_ENGINE.md). Проверенные HTTP-ответы остаются фактами диагностики, но не становятся обучающими метками без сопоставимого эксперимента. Для каждого IP, протокола и метода нужны три соответствующие plain-пробы и три успешные пробы метода. У каждой пары одинаковый заявленный timeout_ms. Plain не должен иметь применённых или пропущенных действий. Успешная проба метода требует ровно одного подтверждённого действия и нуля пропусков в счётчиках конкретного запроса; утрата контекста не допускает обучения. Успешный ответ за пределами собственного бюджета также не допускается. Существующий порог двух IP остаётся неизменным.

Отчёт показывает timeout_ms, applied_delta и skipped_delta для каждого шага. Сводка допуска обучения содержит число исключённых групп (IP, протокол, метод) из-за различного бюджета, неподтверждённого действия или времени. Проверенный HTML без пригодной группы по-прежнему виден в статистике. Это консервативный программный критерий, не подтверждение сетевой эффективности метода. Если Android не передаст контекст счётчиков, обучение будет отклонено; реальная проверка остаётся открытой. Модель, VPN, ROOT, TCP-адаптер, планировщик, обновлятор и подпись не изменены.

Регрессии: разные бюджеты между методами и внутри отдельного IP; отсутствующие, пропущенные и повторные действия; загрязнённый контроль; отрицательное/просроченное время и допустимая граница. Для независимой ветки подключена существующая Android CI без публикации релиза. Результаты CI и физической проверки не заявлены до получения.
