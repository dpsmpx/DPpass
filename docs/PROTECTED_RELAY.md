# Защищённая раздача — D-110

Исправление P-04 аудита Fable 5.2. Оба устройства обновляются; старые
сопряжения выполняются заново. Старые документы сохраняются в карантине,
раздача выключается и получает новые случайные ключи. Скрытого возврата
к SOCKS5 на интерфейсе раздачи нет. Локальный прокси 127.0.0.1 — отдельный
режим, его формат не меняется.

- Транспорт: поддерживаемый закреплённым Xray SS2022 AES-256-GCM.
  Новый алгоритм шифрования в DPpass не добавлен.
- Ключ сервера — 32 случайных байта; у каждого гостя свой независимый
  ключ 32 байта. Отзыв гостя исключает его ключ при переподключении.
- Сопряжение DPPAIR2 сохраняет сравнение кода на двух экранах и передачу
  ключей через существующий ECDH/AES-GCM канал. DPPAIR1 не принимается.
- `dppass.share` v3: server_key, client_key, devices; `dppass.relays`
  v2: server_key/client_key. Исторические Kotlin-поля user/password
  означают соответственно ключ сервера/клиента; у PairedDevice.user —
  идентификатор гостя. На экране показаны названия ключей.
- Ссылка `dppass-relay://` содержит оба секрета. Передавать её только
  доверенному устройству. Старые socks5-ссылки объясняют необходимость
  повторного сопряжения.
- Поиск открывает TCP-порт без отправки данных. Это только кандидат:
  личность не устанавливается TCP accept. Данные проходят через
  зашифрованный SS2022; без нужных ключей проверка соединения не проходит.
  Занятый чужой порт может помешать доступности, но не получает секреты.

Схема ядра: [официальный protobuf](https://github.com/XTLS/Xray-core/blob/b26a91de4f32/proxy/shadowsocks_2022/config.proto),
blob `c73943d4ad297886b8b87a33194541a72378aa0c`;
[JSON-конфигурация](https://github.com/XTLS/Xray-core/blob/b26a91de4f32/infra/conf/shadowsocks.go),
blob `13862dd833afe8fcae6597f6986be6a432955016`. Используются штатные
MultiUserServerConfig, clients и составной ключ server:client.

Проверки: JVM-кодеки/сопряжение/отзыв, отсутствие байтов аутентификации
при поиске, protobuf-политика моста, реальный зашифрованный echo между
двумя Xray с отказом неверного/отозванного ключа. Проверка Android и
Windows на устройствах автора остаётся обязательной.
