# Формат конфигурации DPpass, версия 3

Собственный документ DPpass (D-06): JSON с маркером
`"format": "dppass.config"` и версией формата, не связанной с версиями
ядер, геоданных и приложения. Разбор — `config/` (`ConfigLoader`,
`DocumentMapper`, `ConfigValidator`), запись — `ConfigWriter`. Набор
протоколов — IR v1 (D-16); версия 2 формата (D-37) добавила отпечатки
TLS, управление перегрузкой Hysteria2 и настройки XHTTP, версия 3
(D-107) — Brutal, параметры QUIC и перескок портов Hysteria2.

## 1. Общие правила

- **Строгий JSON**: повторный ключ — `JSON_DUPLICATE_KEY`; лишние данные
  после документа, управляющие символы в строках, неверные числа —
  `JSON_SYNTAX`. Сообщение об ошибке содержит позицию, но не цитату
  входа (там секреты).
- **Неизвестное поле — ошибка** `FIELD_UNKNOWN` (не «пропустить молча»):
  новые поля появляются только с новой версией формата.
- Нет обязательного поля или оно `null` — `FIELD_MISSING`; `null` у
  необязательного — то же, что поле не указано. Не тот тип —
  `FIELD_TYPE`. Значение не из закрытого набора — `VALUE_UNKNOWN` со
  списком допустимых (не «ближайшее похожее»).
- Каждая находка — с путём: `$.profiles[0].security.public_key`.
- **Пределы** (`ConfigLimits`) проверяются до разбора вглубь:

| Предел | Значение | Код |
|---|---|---|
| размер документа | 1 МиБ (UTF-8) | `DOCUMENT_TOO_LARGE` |
| вложенность | 32 | `DOCUMENT_TOO_DEEP` |
| длина строки (и ключа) | 4096 символов | `LIMIT_EXCEEDED` |
| профилей | 512 | `LIMIT_EXCEEDED` |
| правил маршрутизации | 4096 | `LIMIT_EXCEEDED` |
| значений во всех правилах | 100 000 | `LIMIT_EXCEEDED` |

## 2. Документ

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `format` | строка | да | ровно `dppass.config`, иначе `FORMAT_NOT_DPPASS` |
| `format_version` | целое | да | `3`; `1` и `2` — через миграцию (§8); новее — `FORMAT_VERSION_UNSUPPORTED` «создано более новой версией» |

| `dns` | объект | да | DNS (§5) |

## 3. Профиль сервера

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `id` | строка | да | `[a-z0-9][a-z0-9._-]{0,63}`, уникален (`ID_INVALID`, `ID_DUPLICATE`) |
| `name` | строка | да | как `name` документа |
| `server` | строка | да | доменное имя (нижний регистр, IDN — punycode) или IPv4/IPv6 (`HOST_INVALID`) |
| `port` | целое | да | 1…65535 |
| `protocol` | объект | да | §3.1 |
| `transport` | объект | нет | §3.2; нет — `tcp` |
| `security` | объект | да | §3.3 |
| `hints` | объект | нет | `priority` (целое −1000…1000, по умолчанию 0) — порядок в плане подключения; `allowlist_reachable` (по умолчанию `false`) — точка входа доступна из сети в режиме белого списка (утверждение пользователя или поставщика, DPpass его не проверяет, D-13) |

### 3.1. Протокол (`protocol.type`)

| `type` | Поля | Правила |
|---|---|---|
| `vless` | `id` — UUID (секрет); `flow` — `none` (по умолчанию) или `vision` | нужна защита `tls` или `reality` (`SECURITY_REQUIRED`); `vision` — только транспорт `tcp` с `tls`/`reality` (`FLOW_REQUIRES_TCP_TLS`) |
| `trojan` | `password` (секрет) | только с `tls` |
| `shadowsocks` | `method` — `2022-blake3-aes-128-gcm`, `2022-blake3-aes-256-gcm`, `2022-blake3-chacha20-poly1305`; `password` — ключ base64 (16 байт для aes-128, иначе 32; секрет) | защита `none`, транспорт `tcp` (`TRANSPORT_PROTOCOL_MISMATCH`); неверная длина ключа — `PASSWORD_FORMAT_INVALID`. Старые AEAD-методы не поддерживаются (D-16) |
| `hysteria2` | `password` (секрет); `obfs_password` — необязательный (секрет); `congestion` — `bbr` или `reno` (формат 2), `brutal` или `force-brutal` (формат 3; нет — по умолчанию ядра: Xray без скоростей Brutal берёт BBR); `quic` и `hop` — необязательные объекты формата 3 (§3.1.1) | транспорт `native`, защита `tls` |

Секрет не может быть пустым (`PASSWORD_EMPTY`) и не может быть меткой
`<redacted>` из отредактированного экспорта (`SECRET_PLACEHOLDER`: такой
документ можно показать, но не активировать).

#### 3.1.1. Hysteria2: `quic` и `hop` (формат 3)

То, что у Xray 26.9.30 действует на клиенте (D-107): `finalmask.quicParams`
(`transport/internet/hysteria/dialer.go`) и маска `udphop`. Числа — целые
без знака, `0` — то же, что поля нет; пределы — как у ядра
(`infra/conf/transport_internet.go`): что ядро отвергло бы при запуске,
отвергается при чтении — `TRANSPORT_SETTING_INVALID` с путём.

| Поле `quic` | Значение |
|---|---|
| `bbr_profile` | `conservative`, `standard`, `aggressive` |
| `brutal_up`, `brutal_down` | скорость Brutal, **байт** в секунду, ≥ 65536; Xray получает её в битах |
| `brutal_disable_loss_compensation` | логическое |
| `init_stream_receive_window`, `max_stream_receive_window`, `init_connection_receive_window`, `max_connection_receive_window` | байты, ≥ 16384 |
| `max_idle_timeout` | секунды, 4…120 |
| `keep_alive_period` | секунды, 2…60 |
| `disable_path_mtu_discovery`, `disable_chrome_parrot`, `disable_gso` | логическое |

`force-brutal` без `brutal_up` — ошибка (ядро не запустится).

| Поле `hop` | Значение |
|---|---|
| `modes` | непустой массив: `interval_local`, `interval_remote`, `per_conn_remote` |
| `ports` | непустой массив портов сервера: `"N"` или `"N-M"`, 1…65535 |
| `interval` | диапазон секунд `N` или `"N-M"`, начало ≥ 5; нет — 30, как у ядра |

Адреса перескока (`remoteIPs` у Xray) в формате нет: сервер профиля — один
адрес.

### 3.2. Транспорт (`transport.type`)

| `type` | Поля |
|---|---|
| `tcp` | — |
| `websocket` | `path` (обяз.), `host` (домен, необяз.) |
| `httpupgrade` | `path` (обяз.), `host` (необяз.) |
| `xhttp` | `path` (обяз.), `host` (необяз.), `mode` — `auto` (по умолчанию), `packet-up`, `stream-up`, `stream-one`; формат 2 — необязательные настройки ниже |
| `grpc` | `service_name` — 1…256 символов без пробелов |
| `native` | — (свой транспорт протокола; только `hysteria2`) |

`path` начинается с `/`, до 1024 символов, без пробелов и управляющих
(`PATH_INVALID`); `host` — доменное имя (`DOMAIN_INVALID`).

Настройки `xhttp` формата 2 (D-37) — то, что поставщики передают в
`extra` Xray. Диапазон — целое `N` или строка `"N-M"` с N ≤ M (без
знака); `0` — то же, что поля нет (так понимает Xray). Неверное —
`TRANSPORT_SETTING_INVALID` с путём.

| Поле | Значение |
|---|---|
| `x_padding_bytes` | диапазон, начало ≥ 1 — размер заполнения запросов |
| `sc_max_each_post_bytes` | диапазон, начало ≥ 1 — наибольший размер одного POST (`packet-up`) |
| `sc_min_posts_interval_ms` | диапазон, начало ≥ 1 — наименьший промежуток между POST, мс |
| `no_grpc_header` | логическое, по умолчанию `false` |
| `xmux` | объект: `max_concurrency` или `max_connections` (не вместе), `c_max_reuse_times`, `h_max_request_times`, `h_max_reusable_secs` — диапазоны; `h_keep_alive_period` — секунды −1…86400 (отрицательное — без keep-alive). Заданный `xmux` заменяет значения ядра по умолчанию целиком, как в Xray |

### 3.3. Защита (`security.type`)

| `type` | Поля |
|---|---|
| `none` | — (только `shadowsocks`) |
| `tls` | `server_name` (домен, необяз.); `alpn` (массив строк 1…32 символа, необяз.); `fingerprint` — `chrome`, `firefox`, `safari`, `randomized`; с формата 2 ещё `ios`, `android`, `edge`, `360`, `qq`, `random` (один из современных, ядро выбирает при каждом запуске), `randomizednoalpn` (необяз.; без него — отпечаток ядра по умолчанию, у Xray 26.9.30 — `chrome`; `unsafe` — TLS Go без подделки — не принимается). У Hysteria2 в Xray отпечатка нет, а ALPN всегда `h3`: профиль Hysteria2 с `fingerprint` или с `alpn`, отличным от `h3`, компилятор Xray отвергает, а не применяет молча иначе; `allow_insecure`: `true` — ошибка `INSECURE_TLS_REJECTED` (D-11), `false` допускается |
| `reality` | `server_name` (домен, обяз.); `public_key` — 32 байта X25519 в base64url без `=` (43 символа, `REALITY_PUBLIC_KEY_INVALID`); `short_id` — 0…16 шестнадцатеричных цифр в нижнем регистре, чётное число (секрет, `REALITY_SHORT_ID_INVALID`); `fingerprint` (по умолчанию `chrome`); `spider_x` (необяз.) |

REALITY — только с `vless` и транспортом `tcp`, `xhttp` или `grpc`.

## 4. Маршрутизация (`routing`)

Смысл — D-09 и `docs/ARCHITECTURE.md`, §5.

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `default` | `direct` / `proxy` / `block` | `proxy` | действие, если ни одно правило не сработало |
| `domain_resolution` | `never` / `if_no_domain_match` | `never` | применять ли IP-правила к домену после резолва |
| `bypass_lan` | логическое | `true` | локальные сети (RFC 1918, link-local, CGNAT, ULA) мимо туннеля |
| `automatic_domestic` | логическое | `false` | автосплит (D-45): после всех правил отечественное (`geosite:category-ru`, `geoip:ru`) → `direct`. По умолчанию выкл: документ значит ровно то, что в нём; включает политика (режим «авто») |
| `apps` | объект | `{"mode": "all"}` | кто в туннеле: `mode` — `all`, `only`, `except`; `packages` — имена пакетов Android (`PACKAGE_INVALID`) |
| `rules` | массив | `[]` | правила по порядку; первое сработавшее решает |

Правило:

| Поле | Значения |
|---|---|
| `id` | как id профиля, уникален |
| `action` | `direct`, `proxy`, `block` |
| `domain` | точные имена |
| `domain_suffix` | имя или его поддомены (по границе метки: `example.com` не ловит `badexample.com`) |
| `domain_keyword` | подстрока имени |
| `ip_cidr` | подсети `адрес/длина` (без длины — один адрес); биты хоста обнуляются с пометкой `CIDR_HOST_BITS` |
| `geosite`, `geoip` | коды `[a-z0-9][a-z0-9_!@.-]{0,63}` (регистр приводится к нижнему; `GEO_CODE_INVALID`) |
| `apps` | имена пакетов |
| `protocol` | `tcp`, `udp` |
| `port` | `"443"` или `"1000-2000"` (`PORT_RANGE_INVALID`) |
| `network` | `wifi`, `mobile`, `ethernet`, `other` |

Поля условия соединяются через И, значения внутри поля — через ИЛИ;
`domain*` и `geosite` — одно условие «назначение по имени», `ip_cidr` и
`geoip` — «назначение по адресу». Правило без условий — ошибка
`RULE_EMPTY` (для «всего остального» есть `default`). Повтор правила —
`RULE_DUPLICATE`, правило, которое никогда не сработает из-за более
раннего, — `RULE_SHADOWED` (предупреждения); правило `proxy`/`block` для
приложения вне туннеля — ошибка `APP_POLICY_CONFLICT`.

Коды `geosite` и `geoip` (`geosite` — и в правилах DNS, §5) называют
списки набора геоданных DPpass (D-27, D-31). Из чего собран набор,
записано в его оглавлении (`manifest.json`) и показано в локальном
отчёте (коммит dlc, месяц DB-IP).

- `geosite:<список>` — список доменов `v2fly/domain-list-community` по
  имени файла (`category-ru`, `google`). `geosite:<список>@<атрибут>` —
  только записи списка с этим атрибутом (`google@ads`); несколько `@` —
  записи со всеми названными атрибутами сразу.
- `geoip:<страна>` — двухбуквенный код страны по DB-IP «IP to Country
  Lite»: ISO 3166-1 alpha-2 (`ru`, `de`, …) и `xk` (Косово). Пометки
  DB-IP «без страны» (`ZZ`) в наборе нет.
- `geoip:private` — не страна, а своя таблица DPpass
  (`tools/xray/geodata/private.go`): адреса, которые не ведут к узлу в
  интернете.
  - В неё входят блоки реестров особых адресов IANA для IPv4 и IPv6
    (RFC 6890), которые реестр прямо называет недостижимыми глобально
    («Globally Reachable: False»), — в том числе частные сети, CGNAT,
    петля, локальные для канала, уникальные локальные IPv6, адреса для
    документации и замеров, зарезервированные.
  - Внутри блока решает самый узкий блок реестра: `192.0.0.9` (anycast
    PCP) в `private` не входит, хотя `192.0.0.0/24` входит.
  - Блоки, о которых реестр не отвечает («N/A» или пусто: 6to4
    `2002::/16`, Teredo `2001::/32`), в `private` не входят.
  - Кроме реестра, в таблицу входят групповые адреса (`224.0.0.0/4`,
    `ff00::/8`).

`geoip:private` — условие правила для трафика, который уже в туннеле.
`bypass_lan` работает иначе: он выводит из туннеля маршруты локальных
сетей (RFC 1918, link-local, CGNAT, ULA), и до правил этот трафик не
доходит.

На устройстве компилятор сверяет коды и атрибуты с оглавлением
установленного набора:
- кода нет — ошибка `GEO_CODE_UNKNOWN` с путём правила;
- атрибута нет ни у одной записи списка — тоже `GEO_CODE_UNKNOWN`. Само
  ядро такой атрибут не проверяет, и условие молча не срабатывало бы
  (Xray 26.9.30, проверено 5 октября 2026);
- несколько `@` — сочетание: по `geosite:список@a@b` ядро берёт только
  записи, у которых есть все атрибуты сразу. Нет ни одной такой записи —
  `GEO_CODE_UNKNOWN`, даже если каждый атрибут в списке есть. Поэтому
  оглавление набора (с версии 2 его формата) хранит у списка сочетания
  атрибутов его записей, а не атрибуты вразбивку;
- набора нет — `GEODATA_UNAVAILABLE`.

Так правило с кодом, атрибутом или сочетанием атрибутов, которых в
наборе нет, не принимается молча. Пример: в списке `bing` есть записи
`@ads` и записи `@cn`, но ни одной с обоими, и `geosite:bing@ads@cn`
ядро принимает, но не применяет ни к одному имени (проверено 5 октября
2026) — компилятор такое правило отвергает. В наборе DPpass (dlc
`63777333b7dd`, DB-IP 2026-10; замер 6 октября 2026) нет ни одной записи
с двумя атрибутами сразу: у 302 списков атрибуты есть, у 49 из них —
разные атрибуты у разных записей; любое сочетание из двух и более `@`
на этом наборе отвергается.

На хосте коды с набором не сверяются. В `cli` ядра Xray и геоданных
нет: команда `route` прямо называет непроверенными правила с
`geoip`/`geosite`, которые стоят раньше решившего. Эталоны ядро
проверяет на синтетическом наборе, где есть каждый код из эталонов,
пусть пустой (`tools/xray/check_xray.py`). Что само ядро отвергает код,
которого нет в наборе, проверяет тест моста
`TestGeodataUnknownCodeIsRejected`, а конфигурацию с кодами без набора —
`XrayJniTest.geodataWithoutAssetsIsRejected`.

## 5. DNS (`dns`)

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `servers` | массив | — (обяз., не пустой) | серверы, §5.1 |
| `default` | строка | — (обяз.) | id сервера для всего, что не попало в правила (`REFERENCE_UNKNOWN`) |
| `rules` | массив | `[]` | `{domain, domain_suffix, geosite, server}`: какие имена — какому серверу |
| `strategy` | `dual` / `prefer_ipv4` / `prefer_ipv6` / `ipv4_only` / `ipv6_only` | `prefer_ipv4` | стратегия адресов |
| `leak_protection` | логическое | `true` | имена из туннеля не уходят мимо него открыто; сервер по умолчанию напрямую при включённой защите — `DNS_LEAK_RISK` |

Смысл, который обязан сохранить компилятор ядра (D-10; для Xray —
`docs/ARCHITECTURE.md`, §6):

- **Правила** — по порядку, первое сработавшее решает: имя спрашивается
  только у сервера этого правила, а его отказ не уводит имя к другому
  серверу (в том числе мимо туннеля). Имя, не попавшее ни в одно
  правило, — к серверу `default`.
- **`strategy`.** `dual`, `prefer_ipv4`, `prefer_ipv6` — приложения в
  туннеле получают и A, и AAAA (каким адресом соединяться, решает
  приложение); там, где адрес выбирает сам клиент (прямое соединение по
  имени), `prefer_ipv4` берёт сначала IPv4, `prefer_ipv6` — сначала
  IPv6, `dual` — любой. `ipv4_only` и `ipv6_only` — только адреса этого
  семейства: на запрос другого — пустой ответ.

### 5.1. Сервер

| Поле | Значения |
|---|---|
| `id` | как id профиля, уникален |
| `type` | `udp`, `tcp` — `address` = `хост[:порт]` (по умолчанию 53); `tls` — `address` (по умолчанию 853) и `server_name` (необяз.); `https` — `url`, только `https://`; `system` — резолвер физической сети |
| `route` | `tunnel` или `direct`; `system` + `tunnel` — ошибка `DNS_SERVER_INVALID` |

## 6. Нормализация

Только преобразования, которые не меняют смысл (`Normalizer`):
домены — нижний регистр, без завершающей точки; подсети — канонически;
повторы значений внутри поля правила убираются с пометкой
`RULE_VALUE_DUPLICATE`; списки пакетов в `apps` сортируются. Порядок
правил не меняется — он и есть смысл. Нормализация идемпотентна.

## 7. Запись и экспорт

`ConfigWriter` пишет документ текущей версии с явными значениями по
умолчанию. Режимы (D-11):

- `REDACTED` — по умолчанию для экспорта: `protocol.id`,
  `protocol.password`, `protocol.obfs_password`, `security.short_id`
  заменены на `<redacted>`; документ можно показать, но не активировать.
- `FULL` — только для собственного хранилища и явного «экспорт с
  секретами». Полный экспорт загружается обратно в тот же IR.

## 8. Версии и миграции

По D-06: версия новее текущей — отказ; версия, для которой нет цепочки
миграций, — отказ; миграции — явные шаги «N → N+1» над деревом JSON, у
каждой — тест; ни в каком случае не создаётся конфигурация по
умолчанию взамен.

| Версия | Что изменилось | Миграция |
|---|---|---|
| 1 | первая (D-06, D-16) | — |
| 2 | новые отпечатки TLS, `congestion` у Hysteria2, настройки `xhttp` (D-37) | 1 → 2 — тождественная: версия 2 только добавляет; её ждут документы, сохранённые на устройстве до версии 2 (D-07). Отсутствие конструкций версии 2 в документе версии 1 она не проверяет |
| 3 | `brutal` и `force-brutal`, `quic` и `hop` у Hysteria2 (D-107) | 2 → 3 — тождественная, по тем же причинам |

Новое поле, новое значение в закрытом наборе, изменение смысла поля —
это **новая версия формата**: `ConfigFormat.CURRENT_VERSION`, миграция с
тестом, обновление этого документа.

## 9. Ссылки в подписках

Подписка может быть документом DPpass, списком ссылок или списком в
base64 (`PayloadDecoder`). Ссылки — чужой формат без строгой
спецификации, поэтому правило строже: известный параметр переводится в
IR, известный «по умолчанию» принимается, **любой другой делает ссылку
непригодной** (`SHARE_LINK_PARAM_UNSUPPORTED` со списком имён, без
значений).

| Схема | Параметры |
|---|---|
| `vless://UUID@хост:порт?…#имя` | `type` (`tcp`/`raw`, `ws`, `httpupgrade`, `grpc` + `serviceName`, `xhttp`/`splithttp` + `mode` и `extra`), `security` (`none`, `tls`, `reality` + `pbk`, `sid`, `spx`), `sni`, `fp`, `alpn`, `flow` (`xtls-rprx-vision`), `path`, `host`, `encryption` (только `none`), `headerType` (только `none`) |
| `trojan://пароль@хост:порт?…#имя` | те же, кроме `pbk`/`sid`/`spx`/`flow`/`encryption`; `security` по умолчанию `tls` |
| `hysteria2://пароль@хост:порт/?…#имя` (и `hy2://`) | `sni`, `obfs` (только `salamander`) вместе с `obfs-password`, `insecure` (только `0`), `fm` — finalmask Xray: `quicParams` (ключи §3.1.1 в написании Xray — `bbrProfile`, `brutalUp`…; скорость Brutal — строкой вида `100 mbps`, как у ядра; `debug` и серверные `maxIncomingStreams`, `disableStatelessReset` отбрасываются с находкой `SHARE_LINK_PARAM_IGNORED` — на соединение клиента не влияют, D-48) и `udp` — маски `salamander` (только `password`; пароль, отличный от `obfs-password`, — отказ) и `udphop` (`mode`, `remotePorts`, `interval`; D-107); пароль — вся часть до `@`; порт — один (диапазоны портов IR не выражает); защита — TLS без `alpn` и `fingerprint` (§3) |
| `ss://ДАННЫЕ@хост:порт#имя` | без параметров (`plugin` и др. — отказ); ДАННЫЕ — `метод:пароль` в base64 (стандартный или для URL, с `=` или без) либо открыто с %-кодированием (SIP002); метод — только `2022-blake3-*` (D-16): старый AEAD (`chacha20-ietf-poly1305`, `aes-*-gcm`) отвергается с причиной |

`allowInsecure=1`/`insecure=1` — профиль отвергается
(`INSECURE_TLS_REJECTED`). Повторный параметр — ссылка неоднозначна и
отвергается. Другие схемы (`vmess`, `tuic`, …) —
`SHARE_LINK_SCHEME_UNSUPPORTED` («ещё не поддерживается» или
«неизвестна»). Что выдаёт панель Remnawave и что из этого DPpass
выражает — `docs/research/REMNAWAVE_SUBSCRIPTIONS.md`.

`extra` у `xhttp` (формат 2, D-37) — JSON только с ключами
`xPaddingBytes`, `scMaxEachPostBytes`, `scMinPostsIntervalMs`,
`noGRPCHeader`, `xmux` (`maxConcurrency`, `maxConnections`,
`cMaxReuseTimes`, `hMaxRequestTimes`, `hMaxReusableSecs`,
`hKeepAlivePeriod`); значения — как в §3.2, `0` — «не задано». Другой
ключ (`headers`, `downloadSettings`…) — `SHARE_LINK_PARAM_UNSUPPORTED`
с именем `extra.<ключ>`, без значения; у другого транспорта `extra` —
отказ. В `fm` у Hysteria2 прочее — маски `tcp`, другие маски `udp`
(`noise`, `header-custom`…), `packetSize` у `salamander`, `remoteIPs` у
`udphop` — отказ с именем `fm.<ключ>` или `fm.udp[N] (маска тип)`, без
значений. У VLESS и Trojan `fm` пустой или `{}` — как без него; с
содержимым — отказ с именами его ключей и типов масок (D-107). Корпус —
`tests/data/subscriptions/remnawave-format-v2`, `remnawave-fm-finalmask`,
`remnawave-fm-vless`.

Запрос подписки (D-33): собственный `User-Agent` `DPpass/<версия>` и
`x-hwid` — только если пользователь включил идентификатор для этой
подписки. Ответ с `x-hwid-not-supported` или `x-hwid-max-devices-reached`
— заглушка, а не серверы: `SUBSCRIPTION_DEVICE_ID_REQUIRED` или
`SUBSCRIPTION_DEVICE_LIMIT_REACHED`, удачная ревизия не меняется.
Пустой заголовок метаданных — «не задано». id профиля — `<id подписки>.<первые 12 символов SHA-256
ссылки без имени>`: устойчив между обновлениями и не раскрывает
секрет; имя — фрагмент `#…` (до 128 символов) или `хост:порт`. Та же
ссылка под другим именем — тот же сервер: второй профиль с тем же id
пропускается с находкой `SUBSCRIPTION_ENTRY_SKIPPED`; серверов больше,
чем принимает документ (512, §1), — лишние пропускаются так же.

Профили из ссылок проходят ту же проверку, что профили документа
(`ConfigValidator.validateProfile`: в том числе `sni`, `host`, путь и
`serviceName`), и фильтр по возможностям ядра. Корпус —
`tests/data/subscriptions/links-invalid-names`, `links-invalid-paths`.
