## Известные долги (из аудита)

Подробности и обоснование — `docs/audits/INITIAL_ARCHITECTURE_AUDIT.md`.

- [ ] `MainActivity` не запрашивает `POST_NOTIFICATIONS` (Android 13+):
      уведомление сервиса не будет видно без разрешения (этап 4 —
      вместе с интерфейсом; до этого — запись здесь).
- [ ] `SimulatedHealthChecker` лежит в основном коде `connection/` и
      попадает в APK; не используется приложением (`check_modules.py`

      появится своя модель сети.
- [ ] `RouteEvaluator` перебирает правила линейно: ~120 мкс на решение
      при 2000 правил на хосте (`docs/PERFORMANCE_BUDGET.md`, §3). Для
      объяснения решений достаточно; если понадобится массово —
      индекс по суффиксам.
- [ ] `ActivationStore.parse` молча пропускает повреждённые записи
      истории (`mapNotNull`) и записи `active`/`previous`, а при
      повреждённом `next_revision` считает ревизии заново с 1;
      повреждение стоит отмечать находкой, как и прочее содержимое.
- [ ] Проверка зависимостей Gradle (`gradle/verification-metadata.xml`,
      SHA-256): версии закреплены, содержимое артефактов — нет (T10).

- [ ] Тесты на пределы без тестов: `maxProfiles`, `maxRuleValues`,
      `maxEntries` подписки, история активаций (32), тайм-аут проверки
      здоровья (`docs/PERFORMANCE_BUDGET.md`, §2).
- [ ] Устаревшее в сборке: `android.useAndroidX=false` (удаляется в
      AGP 10), `Configuration.setVisible` из плагина `com.android.lint`
      (удаляется в Gradle 11) — разобрать при обновлении по D-18.
- [ ] Форматтер Kotlin не выбран: 78 строк длиннее 160 символов

## На устройстве

Проверено 4 октября 2026 на телефоне автора — Android 15 (API 35),
arm64-v8a, debug APK только с arm64 (журналы D-26):
`libdppassxray.so` загружается, версия ядра сверяется (26.9.30);
пример из оболочки компилируется и принимается ядром (`core.New` на
устройстве) — после исправления имени входа TUN
(`docs/research/BACKEND_STRATEGY.md`, §6); сервис туннеля стартует в
foreground и останавливается с `BACKEND_NOT_AVAILABLE`; журнал пишется
в файл, причины отказа видны целиком, копия в буфер обмена делается при
уходе оболочки, при остановке сервиса и кнопкой.

Проверено 5 октября 2026 на том же телефоне — отладочный APK arm64 с
кодом `4843f8a` (ветка `debug-apk`), журнал D-26:
- набор геоданных перенесён при первом запуске; вместе со сборкой
  `AppGraph` — около 0,5 с от создания активности;
- ядро 26.9.30 загружено, пример активирован;
- `VpnService.Builder` принял `TunnelSpec` на API 35 с `excludeRoute`
  (`bypass_lan`): TUN поднят;
- ядро запущено на его fd;
- проба здоровья (D-32) к синтетическому серверу примера за 2,3 с
  ответила «ни байта» (`ENDPOINT_UNREACHABLE`), TUN закрыт, сервис
  остановлен, журнал скопирован;
- при повторном открытии оболочки пример не импортируется заново.
Сервер примера — документационный адрес, поэтому подключение с ним и не
должно было пройти. Работу `protect()` такой отказ не показывает: с
закрытым защитником вышло бы то же самое. Это проверит только настоящий
сервер.
