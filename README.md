# DPpass — отладочные сборки 0.6.0-dev для проверки на устройстве

Эта ветка нужна только для того, чтобы передать отладочные APK на
устройство автора. К коду проекта она не относится, в `main` не
вливается, истории у неё нет.

**Это не релиз.** Сборка подписана отладочным ключом машины, где её
собрали, и предназначена только для проверки (`TODO.md`, «На
устройстве»).

Версия 0.6.0-dev (versionCode 60), пакет `com.dpsmpx.dppass`, код —
`main` `50f185d`.

Что нового против 0.5.0:
- подписка с одной и той же ссылкой под двумя именами больше не ломает
  состояние при перезапуске (ошибка из журнала 6 октября,
  `STORAGE_CORRUPTED` ← `ID_DUPLICATE`): второй профиль с тем же id
  пропускается с находкой, а активация не сохраняет то, что не
  прочитается при следующем запуске;
- проверки проекта идут через DP Verify (D-50) — для приложения это
  незаметно.

Как собрана: `./gradlew -Pdppass.abiSplit=true :app:assembleDebug` на
коде `50f185d` (Android SDK 36, build-tools 36.0.0, NDK 30.0.16248370,
Go 1.24, JDK 21). Перед этим на том же коде `tools/hostcheck/run.sh
--full` (`dpv run full --ci`) — ✓ 28 проверок. Каждый APK проверен
`tools/hostcheck/check_apk.py --abi <ABI>`:
- разрешения и компоненты;
- код только из утверждённых корней;
- библиотека ядра Xray 26.9.30 — несжатая, выровнена по 16 КБ;
- набор геоданных;
- бюджет 46 МиБ.

Подпись — отладочный ключ этой машины (`apksigner`), SHA-256
сертификата `a10fef70e5b63c2fc98c62f89817ac413565af9858b2490db810603246a9d567`.

**Установка поверх 0.5.0 не получится.** Отладочный ключ у каждой
машины свой, и у сборки 0.5.0 (ветка `apk-0.5.0`) он другой. Поэтому:
1. удалить установленный DPpass (`com.dpsmpx.dppass`);
2. поставить APK своего ABI;
3. заново добавить подписку.

Обновления поверх без удаления даст подписанная сборка ключом `dppass-dev`
(D-35, D-49). Её собирает `tools/release/sign_apks.py`; для этого в
окружении сессии нужны секреты `DPPASS_SIGNING_*`.
